# 2026 교무수첩

「2026학년도 교무수첩 (초등 담임) v2」 PDF와 같은 쪽·탭·내부 링크로 움직이는 웹 수첩입니다. GoodNotes처럼 손글씨만 쓰는 고정 그림이 아니라, 칸을 마우스와 키보드로 채울 수 있습니다.

배포 주소: https://dmlwjd85.github.io/All-in-One-Home/

## 구성

- **580쪽**. 표지부터 스티커까지 PDF와 같은 쪽 번호입니다. 웹에서는 16:9 화면을 채우도록 늘어나고, 링크는 보이는 버튼·날짜·번호 그 자체입니다. 클릭 상자는 PDF 픽셀이 아닙니다.
- **내부 링크 21,194개**는 PDF와 같은 목적지로 연결됩니다. 왼쪽 탭은 PDF 이름 그대로입니다(홈·쓰·연간·주간·하루·학급·학생·출결·상담·수업·업무·태그·공책·칠판). 「쓰」 안이 쓱적입니다. 오른쪽 달 탭(3–2월·스티커), 위쪽 이전/목차/다음, 본문 바로가기도 포함됩니다. `npm run check:hits`가 탭·날짜·번호 매핑을 확인합니다.
- **글꼴**: 나눔스퀘어라운드(R/B/EB), 학교안심 둥근미소, 학교안심 그림일기 — PDF와 같은 계열입니다.
- **편집**: 줄칸·체크·선택 상자로 입력합니다. 로그인하면 그 계정(`artifacts/{appId}/users/{uid}/...`)에만 동기화되고, 로그인하지 않으면 localStorage에 남습니다.
- **기기만**: 건강·민원·학폭·상담(상담 기록, 256–334쪽, `#상담`·`#학부모` 쓱적)은 Firestore로 올리지 않습니다. 클라우드에 남아 있던 복사본은 로그인할 때 이 기기로 내린 뒤 내 계정 문서만 지웁니다.
- **기한 보드**: 업무 목차나 기한 1쪽(405)에서 공문번호·제목·기한을 올리면 할 일/진행/완료로 나누고, D-3·D-day가 붙습니다. 같은 달이 달력 칸에도 보입니다. 줄로 적던 기한과 업무 할 일 쪽에서도 이어집니다.
- **제출물 체크**: 전달 1쪽(458)에서 명렬 번호로 제출을 켜고 끄면, 안 낸 번호로 알림장 문장을 복사할 수 있습니다.
- **칭찬 스티커**: 스티커 목차(563)에서 번호마다 스티커를 모으고, 목표를 채우면 짧게 축하합니다. 우리 반 온도계는 전체 합입니다.
- **쓱적**: 496쪽부터 한 줄 적고 Enter로 남깁니다. `@12`, `#행발`처럼 적으면 그 아이 누가기록으로 옮길 곳을 제안하고, 옮긴 뒤에도 원문은 남습니다. 건강·민원·학폭·상담이 들어간 줄은 이 기기(`homenote_v2_ssugeokSensitive`)에만 있고 Firestore로 올리지 않습니다.
- **백업**: 오른쪽 위 「내보내기」로 JSON 파일을 받습니다. 「가져오기」는 파일을 검사해 항목 건수를 보여 주고, 확인한 뒤에만 해당 항목을 덮어씁니다. 민감·상담 기록도 파일에는 들어 있지만 복원 후에는 다시 이 기기에만 둡니다.

## 쓰는 법

1. Google 로그인 또는 「이 기기에서만 사용」을 고릅니다.
2. 표지를 누르면 홈입니다. 왼쪽·오른쪽 탭과 본문 버튼을 PDF와 같이 눌러 이동합니다.
3. 빈 칸에 바로 타이핑합니다. 방향키로 앞뒤 쪽을 넘길 수 있습니다.
4. 쓱적 탭이나 오른쪽 아래 「쓱적」(Alt+S)에서 한 줄 적습니다. 제안된 곳으로 옮기면 그 쪽 위에 타임라인이 생기고, 「원문」으로 다시 돌아옵니다.

```

```

## 배포

`main`에 push하면 GitHub Actions가 Pages로 빌드·배포합니다.

```bash
VITE_BASE=./ npm run build
```

Google 로그인을 쓰려면 Firebase Authentication에서 Google 제공업체를 켜고, 승인된 도메인에 `localhost`와 `dmlwjd85.github.io`를 넣어야 합니다.

계정별 보안 규칙은 `firestore.rules`에 있습니다. 클라이언트는 `users/{uid}` 만 열고, 예전 `public/data` 는 읽지도 쓰지도 못합니다. 배포 프로젝트는 `.firebaserc`의 `sambong-world-2026`입니다.

```bash
npx firebase deploy --only firestore:rules
```

### 예전 공유 데이터 복사

앱은 예전 경로를 읽지 않습니다. 프로젝트 소유자가 서비스 계정으로 한 번 복사합니다. 스크립트는 원본을 지우지 않습니다.

1. Firebase 콘솔에서 서비스 계정 키 JSON을 받습니다.
2. Authentication에서 기록을 받을 계정의 UID를 확인합니다.
3. 먼저 건수만 보고, 그다음 복사합니다.

```bash
export GOOGLE_APPLICATION_CREDENTIALS=/절대경로/service-account.json
node scripts/migrate-legacy.mjs --uid 대상UID --dry-run
node scripts/migrate-legacy.mjs --uid 대상UID
```

그 계정으로 로그인하면 상담·건강·민원·학폭 문서는 이 기기로 내려가고 계정 클라우드에서는 지워집니다. 예전 `artifacts/home-note-app/public/data` 가 더 이상 필요 없으면 콘솔에서 직접 삭제합니다.

규칙·이전 테스트:

```bash
npm run test:rules
```

## 알려진 차이

- 스티커 시트는 PDF의 그림 스티커 대신 글자 스티커로 골랐습니다. 원본 PNG 묶음은 PDF에 포함되어 있지 않습니다.
- 상단 얇은 도구막대(내보내기·로그아웃)는 웹 계정용이며 PDF에는 없습니다.
- 일부 정보 쪽(사용법 ②)은 「앱에서 타이핑」 안내로 고쳤습니다. GoodNotes 전용 문장은 웹과 맞지 않기 때문입니다.
